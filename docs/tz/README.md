# ТЗ Zakupki MVP

Это **единый источник правды** по продукту и техническим решениям.

| Роль | Как использовать |
|------|------------------|
| Агент-разработчик | Реализует только то, что зафиксировано здесь. Новые решения — сначала в `DECISIONS.md` / `SPEC.md`, потом в код. |
| Агент-тестировщик | Проверяет систему **строго по acceptance criteria** в `SPEC.md` (идентификаторы `AC-*`). |
| Человек | Фиксирует изменения требований здесь же, одним PR/коммитом с кодом. |

## Документы

1. [`SPEC.md`](SPEC.md) — требования, поведение, критерии приёмки (`AC-*`)
2. [`DECISIONS.md`](DECISIONS.md) — архитектурные решения (ADR)
3. [`GLOSSARY.md`](GLOSSARY.md) — термины
4. [`product/`](product/) — продуктовое ТЗ по категоризации (цель 99% L1, ОКПД2/КТРУ, эталон)

## Правила изменений

1. Не менять поведение «тихо» в коде без обновления ТЗ.
2. Каждый `AC-*` должен быть проверяемым (pass/fail).
3. Статус AC: `planned` | `in_progress` | `done` | `blocked`.
4. Если требование спорное — сначала запись в `DECISIONS.md`.
